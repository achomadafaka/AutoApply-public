# Review-first application workflow

Use this workflow for employer applications and freelance proposals. Keep application materials and evidence local and out of version control.

1. **Verify and deduplicate.** Read the live official listing and check that the application is open. Match the employer or buyer and requisition or project ID against the private application ledger. Check alternate URLs and reposts, as well as the same title and location when IDs are missing. Do not reapply to a known or unresolved prior application. Verify a distinct opening before treating a same-employer listing as new.
2. **Choose the strongest evidence.** Separate hard requirements from preferences and logistics. Match the important requirements to direct, transferable or missing evidence. Write from the applicant's actual contribution, deliverable and verified result. Never invent experience or metrics. If a work sample would help, distinguish a new practice demo using synthetic data from past employer or client work.
3. **Prepare the exact review.** Tailor the approved CV layout to the role, state relocation interest without implying residence or legal eligibility, and check text extraction and the rendered PDF. Write a complete, natural profile that introduces the applicant without repeating the skills list. For freelance, spell out the bid, currency, timeline, scope, acceptance checks, exclusions and any attachments. Review exact material form answers and final files before release.
4. **Stop at the review boundary.** AutoApply assists with recognized contact fields on supported forms. It does not answer sensitive screening questions, make commitments, handle site verification, select attachments or submit. The applicant reviews and completes the official form. Do not bypass platform challenges, account restrictions, required payments or browser approvals.
5. **Record evidence promptly.** Add the resulting state and update it only with evidence. A receipt tied to the exact application means **Confirmed**. A verified sent application email without a recipient receipt means **Sent email**. A user-reported submission without a reviewed receipt means **Self reported**. An attempted submission with no clear receipt means **Uncertain**; do not retry. Use **Not sent** or **Approved not sent** when no attempt was made. Count distinct confirmed applications, not drafts, clicks or duplicates.

Copy [the blank CSV template](application-ledger-template.csv) into an ignored local data directory before populating it. It is a manual workflow reference, not an automatic submission or blocking feature in the app. Keep contact information, exact draft answers, attachments, employers and receipt history out of the public repository.
